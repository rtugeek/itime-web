# itime 用户认证

前端使用 Axios 请求 itime v2 接口，Pinia 保存用户资料；`itime-token` 请求头使用登录返回的 accessTokenV2（优先）或 accessToken。密码只在表单和请求中使用，不保存到本地。启动时通过 `/user/profile` 校验会话，1003、1004 或 HTTP 401 清理会话。退出时调用 `/user/logout`，即使网络失败也清除本地状态。

## 配置

将 `.env.example` 复制为 `.env.local`，修改后重启开发服务或重新构建。

- `VITE_ITIME_API_BASE_URL`：接口根地址，默认 `https://itime.fun/api/v2`。
- `VITE_WECHAT_APP_ID`：微信开放平台**网站应用** AppID，必须与后端 WechatService 支持的 AppID 对应。
- `VITE_WECHAT_REDIRECT_URI`：同源公开访问地址，例如 `https://itime.fun/web/`，不包含 hash；其域名必须登记为微信授权回调域名。

微信密钥仅配置在服务端。微信按钮跳转到官方二维码授权页；回调通过一次性 state 和 10 分钟有效期校验后，调用 `/wechat/login`。查询参数会转换为 Vue hash 路由并在交换 code 前从地址栏移除。桌面离线地址与公开回调不同源时，需在部署的网页中完成登录；不支持将另一个浏览器的会话自动导入离线桌面窗口。

## 页面与接口

| 页面 | 接口 |
| --- | --- |
| `/user/sign/in` 邮箱登录 | POST `/user/login/email` |
| `/user/sign/up` 邮箱注册 | POST `/mail/code`（register）、`/mail/register` |
| `/user/password/reset` 找回密码 | POST `/mail/code`（reset）、`/mail/password` |
| `/user/wechat/callback` 微信回调 | POST `/wechat/login` |
| `/user/profile` 账户信息 | GET `/user/profile` |

邮箱表单使用 URLSearchParams 提交，符合 Spring `@RequestParam`，密码不会出现在 URL 中。新密码规则与后端一致：8–16 位英文字母或数字。验证码发送成功后等待 60 秒，服务端仍负责实际限流和校验。

## 同步说明

待办、番茄钟和普通倒计时使用 itime REST 接口进行数据同步。

当前后端 Countdown 没有 recurrence 字段，因此重复倒计时保留在本地并维持待同步状态，不上传或覆盖其重复规则。倒计时删除为物理删除：前端仅在完整分页读取成功后，清理本账户曾同步且未再修改的缺失记录；未上传的新建或本地编辑继续保留。

## 验证

运行 `node node_modules/vitest/vitest.mjs run test/auth`。测试覆盖表单编码、令牌、会话退出、业务错误及微信回调状态校验。真实邮件投递与微信授权需要部署配置和真实账户验证。


### 倒计时同步

`CountdownApi` 按 Java DTO 显式映射字段。`syncId` 保存服务端数字业务 ID，本地字符串 ID 保持不变；`syncAccount`、`lastSyncedAt` 记录已确认的账户和版本。失败重试沿用已持久化的数字 ID。纯日期按本地日历日期转换，避免 UTC 截断导致日期偏移。

保存、删除、登录及页面初始化会触发同步；列表提供手动同步，并在联网恢复和每 5 分钟重试。同步完成刷新当前列表并广播给其他窗口。单条失败不会阻止其余条目，错误显示在倒计时列表。并发冲突采用保留待上传本地编辑的策略；上传期间产生的新编辑继续标记为待同步。服务端没有版本条件写入，不能保证跨设备同时修改时的强一致性。


### 番茄钟同步

场景和记录使用各自的 REST 列表、保存和删除接口。同步先完成场景，再同步记录；场景失败时保留记录等待重试。场景关联统一使用场景的字符串 id，旧云端 UUID 不参与上传，不执行旧数据迁移。

历史记录没有 updateTime 字段，因此使用完整分页列表和已确认字段快照检测远端变化，不发送增量 updateTime 参数。当前后端 Gson 将 finishTime 序列化为 `name`：上传和下载显式适配，且兼容后续修正为 finishTime 的响应。duration 保持接口规定的秒数。

同步失败保留脏数据，上传期间的新编辑仍待同步。完整快照中缺失的已同步干净数据按远端删除处理；场景删除同步清理关联记录，避免记录被再次上传。列表、详情统计及历史页面随同步和跨窗口广播刷新，提供手动同步、每 5 分钟重试及联网恢复重试。

冲突优先保留待上传的本地编辑。后端没有条件版本写入或删除日志，跨设备同时编辑仍可能以最后一次成功写入为准。真实接口联调需要登录账户，本地测试使用模拟接口。


### Todo 与生日同步

Todo 和生日复用 `SnapshotSync` 的完整分页、账户校验、版本快照、独立失败重试和并发编辑保护。Todo 显式传输完成时间、提醒、排序、开始时间和重复规则；清空可选字段时发送 null，排除本地元数据和 userId，记录标识统一使用 id。同步完成会刷新待办/已完成列表及提醒计划。

生日保留独立年月日和 dateType，农历负月份（闰月）不做公历转换。上传与下载保留服务端时间戳；普通编辑才更新本地更新时间。删除先保存本地标记，成功请求 DELETE 或确认远端已不存在后才标记同步完成。干净且曾确认同步的缺失记录可按远端删除处理，失败分页不触发此操作。

两项均支持登录、页面初始化、编辑和删除触发同步，提供手动同步、每 5 分钟重试和联网恢复重试，并广播列表刷新。新的生日持久化 ID 在缺省时使用安全整数随机时间 ID，减少跨设备自增键冲突。旧数字业务 ID 保持不变。跨设备同时编辑采用本地待同步编辑优先，后端不支持条件版本更新。
